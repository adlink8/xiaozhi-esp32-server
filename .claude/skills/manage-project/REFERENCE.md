# Priority Scoring Framework

> 该文档为 `-next` 提供优先级评分标准。

## 与 todo.md 结构化任务格式的关系

- 如果任务包含 `scores`（impact/effort/risk/dependencies/urgency），应 **直接使用用户提供的分值**（最稳定）。
- 如果缺失 `scores`，才基于代码扫描信号、文档状态、git 动态进行推断（更主观）。

---

详细的任务优先级评分系统，用于 `-next` 命令自动排序。

## 评分维度

每个任务按以下 5 个维度评分（0-10 分），总分 = 加权和。

### 1. Impact (权重 40%)

**定义**：任务完成后对项目的影响有多大？

| Score | Criteria | Example |
|-------|----------|---------|
| 10 | 阻塞主链路，不做会导致项目无法继续 | ASR 服务故障，语音链路无法工作 |
| 8 | 影响多个功能模块或核心用户场景 | manager-api 用户认证系统，设备接入 |
| 6 | 影响单个重要功能，但有 workaround | OTA 升级界面，设备列表筛选 |
| 4 | 影响次要功能或用户体验 | Web UI 美化，日志可视化 |
| 2 | 本地改进或文档优化 | 添加代码注释，更新 README |
| 0 | 无影响，可有可无 | 删除过时文件，代码风格调整 |

### 2. Effort (权重 -20%, 减分)

**定义**：完成这个任务需要多少工作量？

| Score | Time | Complexity | Example |
|-------|------|-----------|---------|
| 10 | >5 天 | 需要设计+多文件改动+测试 | 重构 WebSocket 架构 |
| 7 | 3-5 天 | 中等复杂度，涉及多个模块 | 完整的 OTA 升级功能 |
| 4 | 1-3 天 | 相对独立，中等代码量 | 添加设备分组功能 |
| 2 | 2-4 小时 | 简单，代码改动少 | 修复日志格式 |
| 0 | <1 小时 | 极简，一句修改 | 调整常数或颜色 |

**注意**：高 effort = 低优先级（因此减分）。即使 impact 很高，如果需要 1 周才能完成，可能需要拆分。

### 3. Risk (权重 20%)

**定义**：这个任务如果做错了会有多严重的后果？

| Score | Risk Level | Example |
|-------|-----------|---------|
| 10 | 会导致数据丢失、安全漏洞或用户数据泄露 | API 密钥管理、数据库 migration |
| 7 | 会导致功能无法使用或系统崩溃 | MQTT 网关配置、内存泄漏 |
| 4 | 会导致某些场景下的异常或体验下降 | 错误处理、超时配置 |
| 2 | 低风险，最多导致局部重做 | UI 文案、日志格式 |
| 0 | 无风险，随时可以回滚或忽略 | 注释、文档 |

### 4. Dependencies (权重 15%)

**定义**：有多少其他任务依赖于这个任务？

| Score | Blocking Count | Example |
|-------|----------------|---------|
| 10 | 3+ 个关键任务等待 | 设备认证系统，底层网络配置 |
| 7 | 1-2 个重要任务等待 | manager-api 数据模型，ASR 接入 |
| 4 | 少数非关键任务等待 | Web 前端布局，LLM 集成 |
| 2 | 仅有可选任务依赖 | UI 优化、文档增强 |
| 0 | 无依赖，完全独立 | 代码注释、README 更新 |

### 5. Urgency (权重 5%)

**定义**：这个任务有截止日期或外部压力吗？

| Score | Urgency | Example |
|-------|---------|---------|
| 10 | 今天或明天必须完成 | 产品发布前的关键 bug、紧急客户需求 |
| 7 | 本周必须完成 | 计划内的功能交付 |
| 4 | 本月内完成 | 中期目标 |
| 2 | 有计划但无紧急时间 | 长期优化 |
| 0 | 无时间压力 | backlog 项 |

---

## 优先级计算公式

```
Priority Score = (Impact×0.4 - Effort×0.2 + Risk×0.2 + Dependencies×0.15 + Urgency×0.05) × 100
                / (10×0.4 + 10×0.2 + 10×0.2 + 10×0.15 + 10×0.05)

= (Impact×0.4 - Effort×0.2 + Risk×0.2 + Dependencies×0.15 + Urgency×0.05) × 10

Score ∈ [0, 100]
```

### 优先级映射

| Score Range | Priority Level | Color | Action |
|------------|---|-------|--------|
| 80-100 | 🔴 Critical Now | Red | 立即开始，可暂停其他 |
| 60-79 | 🟠 High Priority | Orange | 本周内开始 |
| 40-59 | 🟡 Medium | Yellow | 计划内，适时启动 |
| 20-39 | 🟢 Low Priority | Green | 待分配时间 |
| 0-19 | ⚪ Backlog | Gray | 长期 or 可选 |

## 实例计算

### 例 1：修复 ASR 服务故障

```
Impact: 10 (阻塞主链路语音)
Effort: 6 (涉及 Python + 配置，1-2 天)
Risk: 8 (影响核心功能)
Dependencies: 9 (7 个任务在等待语音链路)
Urgency: 10 (今天项目无法用)

Score = (10×0.4 - 6×0.2 + 8×0.2 + 9×0.15 + 10×0.05) × 10
      = (4 - 1.2 + 1.6 + 1.35 + 0.5) × 10
      = 6.25 × 10 = 62.5
      
→ 🟠 High Priority (本周内)
```

### 例 2：为 Web UI 添加暗黑模式

```
Impact: 3 (只改进 UX，功能无变化)
Effort: 8 (涉及全局样式改动，3-4 天)
Risk: 1 (仅 CSS，无逻辑风险)
Dependencies: 0 (无其他任务依赖)
Urgency: 1 (无时间压力)

Score = (3×0.4 - 8×0.2 + 1×0.2 + 0×0.15 + 1×0.05) × 10
      = (1.2 - 1.6 + 0.2 + 0 + 0.05) × 10
      = -0.15 × 10 = -1.5
      
→ ⚪ Backlog (defer)
```

### 例 3：修复 MQTT 连接超时问题

```
Impact: 9 (不修复设备间通信不稳定)
Effort: 4 (定位问题+调整参数，半天)
Risk: 7 (网络配置有失败风险)
Dependencies: 6 (2-3 设备管理任务依赖)
Urgency: 3 (已计划，但不紧迫)

Score = (9×0.4 - 4×0.2 + 7×0.2 + 6×0.15 + 3×0.05) × 10
      = (3.6 - 0.8 + 1.4 + 0.9 + 0.15) × 10
      = 5.25 × 10 = 52.5
      
→ 🟡 Medium (本月内，适时启动)
```

## 特殊情况处理

### 应该上调优先级的情况

- **生产环境 Bug**：自动 +30 分（从 Medium 升至 High）
- **安全漏洞**：自动 +50 分（无论其他因子，都是 Critical）
- **多个用户反馈的问题**：+15 分（反映真实需求）
- **完全阻塞主功能**：自动升至 Critical（>80 分）

### 应该下调优先级的情况

- **可以 workaround 的问题**：-20 分
- **非主路径的边界情况**：-10 分
- **仅文档或注释**：-15 分
- **已弃用或计划移除的代码**：-25 分（可能不值得改）

---

## 使用流程

1. **扫描 `todo.md` 中的所有任务**
2. **为每个任务填充 5 个维度的分值**
3. **计算 Priority Score**
4. **按分值排序，从高到低列出**
5. **显示阻塞关系**（任务 A 需要 B 先完成）
6. **给出"为什么这是下一个"的解释**

## 自动检测信号

AI 应该根据代码和文档自动推断分值：

| 信号 | 意含 | 自动赋值 |
|------|------|--------|
| 代码有 `FIXME` 注释 | 已知问题 | Impact ↑, Risk ↑ |
| 代码有 `TODO` 注释 | 待完成功能 | Impact ↓, Effort ↓ |
| 多个文件引用同一模块 | 高耦合，改动有风险 | Risk ↑ |
| 最近 commit 涉及该功能 | 在进行中 | Urgency ↑, Dependencies ↓ |
| 项目状态文档标记为 🚧 | 开发中，优先级升高 | Priority ↑20 分 |
| 3+ 个 TODO 指向同一个功能 | 被多个任务等待 | Dependencies ↑ |
